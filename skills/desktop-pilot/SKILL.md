# 操控 Windows 电脑

Desktop Pilot 的工具名都带电脑名前缀，例如 `laptop_screenshot` 表示操作名为 laptop 的电脑。下文用 `<pc>_` 代指前缀。

## 先确定是哪台电脑

- 只有一组工具时直接使用。
- 有多组前缀（如 `laptop_`、`pc_`）而用户没说清楚是哪台时，先问用户，不要猜。
- 同一个任务里不要混用不同电脑的工具。

## 先选对工具

能不碰界面就不碰界面，按下面的顺序考虑：

| 需求 | 用什么 |
| --- | --- |
| 只是想读网页内容 | `<pc>_scrape`，比截图快得多，也省 token |
| 查系统信息、批量处理文件、运行脚本 | `<pc>_shell`（PowerShell） |
| 读写、复制、移动、删除、查找文件 | `<pc>_file` |
| 看哪些程序在运行、结束卡死的程序 | `<pc>_process` |
| 读写注册表 | `<pc>_registry` |
| 打开、切换、最大化、调整窗口 | `<pc>_app` |
| 必须在图形界面里操作（点按钮、填表单、浏览需要登录的网页） | 截图 + 点击/输入，见下一节 |

## 操作界面的基本循环

1. **先看**：调用 `<pc>_screenshot`。可交互元素都画了带编号的彩色框，结果里列出了编号、类型、名称和中心坐标；红色十字是鼠标位置。
2. **再动**：优先用编号（`label`）。编号由系统直接给出元素的真实位置，比任何坐标都准。
3. **再看**：每做完一步、界面可能变化时，重新截图确认结果，再决定下一步。不要凭想象连续操作。

编号只对最近一次截图有效。界面变化后（打开了新窗口、页面跳转、弹出菜单），旧编号可能指向别的东西，必须重新截图。

## 坐标规则

只有在没有编号时才用坐标（游戏、画布、远程桌面、截图里没框住的地方）。

- 坐标以**最近一张图片**为准。截图结果里的「坐标规则」一行说明了取值范围：通常是千分比坐标（x、y 都是 0~1000，左上角是 (0,0)）；也可能是图片像素坐标。按它说的来，**不要自己换算缩放比例**，服务端会处理。
- 目标太小、看不清或者怕点偏时，先用 `<pc>_zoom` 框选那一块区域放大。放大之后，坐标改为以放大图为准，直到下次截图；编号保持不变。
- 点完之后看返回的「鼠标实际位置」，必要时截图确认有没有点中。

## 常见场景

- **打开程序**：`<pc>_app` 的 `launch`（按开始菜单名称模糊匹配，中英文都可以），然后 `<pc>_wait` 等 1~3 秒再截图。已经开着的程序用 `switch` 切到前台。
- **输入文字**：`<pc>_type` 传 `label` 会先点击再输入；要替换原有内容加 `clear=true`；要提交加 `press_enter=true`。中文可以直接输入。
- **填表单**：多个输入框用 `<pc>_multi_type` 一次填完，然后截图核对。
- **多选文件或列表项**：`<pc>_multi_click` 配合 `hold_ctrl=true`。
- **快捷键**：`<pc>_hotkey`，例如 `ctrl+c`、`ctrl+v`、`alt+tab`、`win+d`、`f5`。
- **长页面**：`<pc>_scroll` 滚动后重新截图。网页内容很长时优先用 `<pc>_scrape` 分段读取（结果里会提示下一段的 `offset`）。
- **程序没反应或加载慢**：`<pc>_wait` 后再截图，不要反复点击同一个按钮。
- **截图里没有编号**：说明这个界面读不到元素（游戏、自绘界面、部分 Electron 应用），改用坐标，必要时先放大。
- **启动图形程序**：在 `<pc>_shell` 里要用 `Start-Process`，否则命令会一直等到程序关闭才返回。

## 安全底线

这些工具在用户的真实电脑上执行，后果是真实的：

- **先确认再执行**：删除文件或文件夹、结束进程、修改或删除注册表、执行会改动系统的命令（安装或卸载软件、修改系统设置、改动网络或防火墙）、发送消息或邮件、提交表单或付款之前，告诉用户你要做什么，得到同意再做。
- **绝不擅自执行**：关机、重启、注销、锁屏、修改账户或密码、关闭安全软件、格式化磁盘、清空回收站。
- 用户可能正在用这台电脑，你的点击和输入会打断用户手上的事。操作前简单告知。
- 遇到登录、验证码、支付密码等需要用户本人输入的内容，停下来让用户自己处理，不要尝试填写。
- 工具返回「权限不足」「已被禁用」时，直接告诉用户，不要换个工具绕过去。
- 截图和文件内容可能包含隐私，除非用户要求，不要把截图转发到聊天里，只汇报结论。

## 汇报

做完后用一两句话告诉用户结果。没成功时说明卡在哪一步、看到了什么，而不是笼统地说「失败了」。
